# Control Room — Private Operations Dashboard

`ops.investorpass.com` → same Vercel deployment, `/ops/*` path namespace.
**Private, read-only, server-gated.** Not a public product feature.

## Architecture

- Same Next.js app + Prisma layer (no duplicated DB code, no second app — the repo already runs one deployment).
- **Software graph** (`/ops/architecture`): committed deterministic snapshot `src/data/ops/arch-graph.json` generated by `scripts/gen-arch-graph.ts` (static `@/` import scan + Prisma models). Graphify (Graphify-Labs/graphify, Apache-2.0, Python CLI) is an OPTIONAL deeper analyzer for local use; the dashboard renders the committed snapshot and the public product depends on neither.
- **Evidence graph** (`/ops/evidence-graph`): live domain queries (`/api/ops/graph?q=`) — investor → decision → company → outcome chains with real counts. Distinct from the software graph by design.
- `/ops/data` real per-investor counts; `/ops/integrity` the §53 checks (10-min cache); `/ops/issues` auto-feed + acknowledge (AppConfig KV `ops:ack:*`); `/ops/agents` run registry (AppConfig `ops:agent:*`, registered via `scripts/ops-log-agent.ts`); `/ops/changes` public GitHub API; `/ops/deployments` live route probes + committed QA snapshot (`src/data/ops/qa-snapshot.json` via `scripts/ops-qa-snapshot.ts`); `/ops/docs` reads the deployed docs folder.

## Auth & security model

- Single operator password (8-digit), **scrypt-hashed** (`src/lib/ops/auth.ts`). Plaintext never in client code, NEXT_PUBLIC vars, logs, git, or docs. Override/rotate via `OPS_PASSWORD_HASH` env (generate: scrypt N=16384 r=8 p=1, format `scrypt$N$r$p$salt$key`).
- Session: HMAC-SHA256-signed token (`ops.<exp>.<nonce>`), HttpOnly + Secure + SameSite=Strict cookie, 12h TTL. Edge **middleware** (`src/middleware.ts`) verifies the HMAC before ANY `/ops` or `/api/ops` handler executes (Web Crypto — no DB at the edge). Unauthenticated: pages → redirect `/ops/login`; APIs → 401 JSON.
- Brute force: 5 attempts / 15 min / IP (`loginGate`), generic "Access denied" (no partial-correctness leaks), format check before scrypt.
- Every ops response: `X-Robots-Tag: noindex, nofollow` + `no-store`; `/ops` disallowed in robots.txt.
- Mutations limited to: login/logout, ack issue, integrity re-run, health check. **No destructive actions.**
- Secrets: dashboard renders config *presence* only — never values.

## Subdomain setup (owner, one-time)

1. Vercel project → Settings → Domains → Add `ops.investorpass.com` (keeps `investorpass.vercel.app` untouched).
2. DNS at your registrar: `ops` CNAME → `cname.vercel-dns.com` (Vercel shows the exact record).
3. Optional hardening env (Vercel → Settings → Environment Variables):
   - `OPS_SECRET` (random 64-hex) — rotates the session-signing key;
   - `OPS_PASSWORD_HASH` — new scrypt string to change the operator password.
4. No code changes needed — the path gate serves both origins.

## Environment variables

| Var | Required | Purpose |
| --- | --- | --- |
| `OPS_SECRET` | optional | Overrides baked session-signing secret |
| `OPS_PASSWORD_HASH` | optional | Overrides baked password hash (rotation) |
| `DATABASE_URL` | existing | Live counts/integrity (already set) |
| `PUBLIC_SITE_URL` | existing | Health probe base |

## Known limitations

- Build/typecheck/tests statuses come from the committed QA snapshot (serverless can't compile per-request); regenerate with `scripts/ops-qa-snapshot.ts` after each gate.
- Evidence-graph node cap ~80 per query (read-only performance guard).
- Agent registry requires manual/scripted registration (deliberately lightweight).
- Payments/ESP health = configuration presence only.
